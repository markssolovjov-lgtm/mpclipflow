# MP ClipFlow

**Платформа автоматизации TikTok-контента с рекламными баннерами.** Created by MP Production.

Загрузите длинное видео → выберите длительность роликов и правила нарезки → добавьте рекламный баннер и секунду его появления → MP ClipFlow нарежет видео через FFmpeg, вставит рекламу в каждый ролик, проверит результат и опубликует ролики в TikTok по расписанию через официальный Content Posting API.

## Возможности

| Раздел | Что реализовано |
|---|---|
| **Панель управления** | Счётчики по реальным данным БД, ближайшая публикация, статус TikTok и фоновых обработчиков, график за 14 дней, последние действия, быстрые действия, пустое состояние |
| **Проекты** | Создание, редактирование, архив, копирование (без копирования видеофайлов), удаление (исходники остаются в библиотеке), история обработки и публикаций |
| **Загрузка видео** | Протокол **tus**: выбор файлов и drag-and-drop, несколько файлов, прогресс и скорость, пауза/продолжение, докачка после обрыва и после перезагрузки страницы, отмена. Без лимитов длительности и размера на уровне приложения |
| **Проверка файлов** | ffprobe: реальная длительность, разрешение, FPS, кодеки, звук, формат; понятная причина для повреждённых/неподдерживаемых файлов; миниатюры |
| **Нарезка** | Режим A — последовательная (остаток: сохранить/пропустить), B — ручной выбор на таймлайне, C — равномерная автоматическая выборка. Начало/конец диапазона, интервал между фрагментами, количество, порядок, формат кадра (9:16, 1:1, 4:5, 16:9, исходный), разрешение, FPS, качество, звук |
| **Рекламные баннеры** | Библиотека PNG/JPEG/WebP (тип проверяется по содержимому), категории, кампании, поиск и фильтры, параметры по умолчанию |
| **Вставка рекламы** | Время появления **относительно начала каждого итогового ролика**, длительность, 9 позиций + произвольная + полный экран, размер, отступы, прозрачность, анимации (проявление/выезд), несколько правил, предупреждение при выходе за длительность ролика. Пропорции изображения всегда сохраняются |
| **Редактор** | Плеер с предпросмотром итогового кадра, таймлайн исходника с фрагментами и маркерами, таймлайн ролика с перетаскиваемыми полосами рекламы, кнопка «Проверить рекламу», горячие клавиши (Пробел, I, O). Предпросмотр использует **те же функции геометрии**, что и FFmpeg |
| **Видеопроцессинг** | FFmpeg в фоновых задачах: вырезка, масштабирование, формат кадра (обрезка / поля / размытый фон), наложение баннеров, кодирование H.264/AAC, проверка результата ffprobe, отмена, повтор, восстановление после перезапуска |
| **Пакетная обработка** | Несколько исходников одной операцией; количество роликов — из фактической длительности; очередь с ограничением параллелизма и проверкой места на диске |
| **Библиотека роликов** | Сетка/таблица, фильтры по проекту, статусу публикации и дате, мультивыбор, массовые действия, просмотр, скачивание, повторная обработка, переопределение описания и хештегов |
| **Описание и хештеги** | Шаблоны описаний (`{title} {project} {n} {date}`), наборы хештегов, переопределение для ролика, предпросмотр итогового текста, проверка лимита TikTok 2200 символов и допустимых символов |
| **Расписание** | Дата/время/часовой пояс, интервал (минуты, часы, дни, недели), дни недели, окно публикаций, количество, порядок, авто-добавление новых роликов. Календарь неделя/месяц, перенос, пауза/возобновление, пропуск, изменение порядка, удаление задания без удаления ролика, повтор, история. Учитывается летнее/зимнее время |
| **TikTok** | OAuth (Login Kit), шифрование токенов AES-256-GCM, автоматическое обновление токенов, creator_info, диагностика, повторная авторизация, отключение с отзывом токена |
| **Автопубликация** | Серверный планировщик на БД: preflight → init → загрузка чанками → подтверждение статуса через API. Повторы с экспоненциальной задержкой, лимит попыток, защита от дублей (уникальный частичный индекс + атомарный захват), журнал попыток, ручной повтор |
| **Мастер серии** | 8 шагов: исходники → нарезка → реклама → предпросмотр → метаданные → расписание → проверка → запуск. Черновик сохраняется в браузере |
| **Мониторинг** | Состояние БД, обработчиков, очередей, хранилища, интеграции, последние ошибки; журнал действий без секретов |
| **Безопасность** | Сессии в httpOnly-cookie (хэш токена в БД), argon2, проверка владельца на каждом запросе и для каждого файла, CSRF-заголовок, rate limiting, helmet/CSP, секреты только на сервере |

## Архитектура

```
apps/web          React + TypeScript + Tailwind (Vite)        — интерфейс
apps/server       Node.js + TypeScript + Express + Prisma     — API, воркеры
packages/shared   общая логика (zod-схемы, нарезка, геометрия баннера,
                  расписание, подписи) — одна и та же для предпросмотра и рендера
PostgreSQL        данные и очереди заданий
FFmpeg/ffprobe    обработка видео
Хранилище         локальный диск или S3-совместимое (AWS S3, MinIO, R2, Yandex)
```

**Почему без Redis/BullMQ.** Очереди рендера и публикаций хранятся в PostgreSQL и захватываются атомарно (`FOR UPDATE SKIP LOCKED`) с «арендой» и heartbeat. Это даёт сохранность после перезапуска, несколько воркеров без дублей и одну зависимость вместо двух.

```
apps/server/src
├── auth/               регистрация, вход, сессии, CSRF, rate limit
├── routes/             projects, media (sources/banners/templates/renders), library,
│                       publishing (schedules/jobs), tiktok, overview (dashboard/system/wizard), files
├── services/           projects (план и постановка рендеров), sources (ffprobe),
│                       uploads (tus), schedules, captions, tiktok/{client,service}
├── media/              ffmpeg (probe, запуск, прогресс, ошибки), renderCommand (граф фильтров)
├── workers/            render (рендер-воркер), publisher (планировщик публикаций), index
├── storage/            LocalStorage / S3Storage (потоки, диапазоны, multipart)
└── lib/                http, crypto, activity log
```

Схема данных — [`apps/server/prisma/schema.prisma`](apps/server/prisma/schema.prisma): Users, Sessions, ConnectedAccounts, Projects, ProjectSources, SourceVideos, UploadSessions, AdBanners, AdCampaigns, VideoSegments, RenderJobs, RenderedVideos, HashtagTemplates, PublishingSchedules, PublishingJobs, PublishingAttempts, ActivityLogs, WorkerHeartbeat.

## Быстрый старт (разработка)

Требуется **Node.js 20+**. FFmpeg ставится автоматически (`ffmpeg-static`, `ffprobe-static`); можно указать свой через `FFMPEG_PATH`/`FFPROBE_PATH`.

```bash
npm install
```

```bash
cp .env.example .env
```

Сгенерируйте ключ шифрования токенов и вставьте в `TOKEN_ENCRYPTION_KEY`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

**База данных** — один из вариантов:

```bash
docker compose up -d postgres
```

или без Docker (локальный PostgreSQL из npm-пакета, работает, пока открыт процесс):

```bash
npm run db:local
```

Применить миграции:

```bash
npm run db:migrate
```

Запуск API (порт 8080, вместе с фоновыми обработчиками) и интерфейса (порт 5173):

```bash
npm run dev:server
```

```bash
npm run dev:web
```

Откройте http://localhost:5173 и зарегистрируйтесь.

## Тесты

```bash
npm test
```

Серверные интеграционные тесты используют отдельную базу `clipflow_test` (создаётся автоматически; очищаются только базы с суффиксом `_test`) и **безопасный режим TikTok** — HTTP-транспорт подменён, реальных запросов и публикаций нет.

Покрыто: загрузка и возобновление (tus), поток большого файла без роста памяти (256 МБ), видео разной длительности (в т.ч. 10 часов — в расчёте), последовательная/ручная/авто нарезка, вставка баннера в каждый ролик и **проверка по кадрам**, что баннер появляется на нужной секунде итогового ролика, сохранение пропорций, полный экран, пакетная обработка, подписи и хештеги, расчёт расписания (включая переход на летнее время), сохранение очереди после перезапуска, защита от дублей, ошибки FFmpeg, ошибки авторизации TikTok, обновление токена, повторы и лимит попыток, восстановление прерванных рендеров и публикаций, изоляция пользователей, CSRF, Range-запросы, мастер серии.

## Настройка TikTok

1. Создайте приложение на [developers.tiktok.com](https://developers.tiktok.com/) (тип Web).
2. Добавьте продукты **Login Kit** и **Content Posting API** (для автопубликации включите **Direct Post**).
3. Redirect URI: `https://<ваш-домен>/api/tiktok/callback` — TikTok требует HTTPS на публичном домене. Для разработки используйте туннель (например, cloudflared/ngrok) и укажите его адрес в `TIKTOK_REDIRECT_URI` и `PUBLIC_URL`.
4. Разрешения: `user.info.basic`, `video.upload`, `video.publish`.
5. Заполните `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `TIKTOK_REDIRECT_URI` и перезапустите сервер. Затем «TikTok → Подключить».

**Ограничения платформы (честно):**

- Пока приложение **не прошло аудит** TikTok, прямые публикации возможны только с приватностью «Только я» (`SELF_ONLY`) и для ограниченного числа пользователей. После аудита — любые разрешённые аккаунту уровни.
- Режим **«Во входящие»** (`video.upload`) работает без Direct Post: ролик загружается черновиком, пользователь завершает публикацию в приложении TikTok. Подпись в этом режиме TikTok не принимает — её можно скопировать из карточки публикации.
- Публикация считается успешной **только** после статуса `PUBLISH_COMPLETE` (или `SEND_TO_USER_INBOX` для режима «Во входящие») от API.
- Лимиты TikTok: до 4 ГБ на файл, видео до 10 минут через API (максимум для аккаунта — из creator_info), FPS 23–60, стороны 360–4096 px, 6 init-запросов в минуту на токен.
- Браузерная автоматизация и неофициальные методы не используются.

## Развёртывание

### Docker

```bash
docker compose --profile full up -d --build
```

Образ включает API, собранный интерфейс и системный FFmpeg; миграции применяются при старте. Данные — в томе `appdata` (`/app/data`). Для продакшена задайте в `.env`: `NODE_ENV=production`, `PUBLIC_URL=https://…`, `TOKEN_ENCRYPTION_KEY`, ключи TikTok.

### Масштабирование

- **Отдельные воркеры:** `RUN_WORKERS_IN_API=false` в API и сколько угодно процессов `npm run start:worker`. Задания распределяются без дублей.
- **Параллельные рендеры:** `RENDER_CONCURRENCY` на воркер.
- **Большие объёмы:** `STORAGE_DRIVER=s3` + `S3_*` — загрузки идут напрямую в S3 multipart (tus S3 store), FFmpeg читает исходник по подписанной ссылке с HTTP Range, без скачивания целиком. Локально можно поднять MinIO: `docker compose --profile s3 up -d minio`.
- **Запас места:** `MIN_FREE_DISK_MB` — при нехватке места новые загрузки отклоняются, рендеры ждут в очереди. Это защита инфраструктуры, а не лимит размера видео.

### Без Docker

```bash
npm run build
```

```bash
npm run db:deploy
```

```bash
npm start
```

За обратным прокси (nginx) отключите буферизацию и лимит тела для `/api/uploads/tus` (`client_max_body_size 0; proxy_request_buffering off;`).

## Что важно знать

- **ИИ-анализ не реализован.** Режим C — равномерная выборка фрагментов; поле `autoStrategy` и модуль нарезки готовы к добавлению детектора сцен и анализа речи.
- **S3-драйвер** реализован (хранилище, tus S3 store, подписанные ссылки), но автоматические тесты выполняются на локальном хранилище.
- **Реальные вызовы TikTok API** проверены тестами только в безопасном режиме (подменённый транспорт) по официальной документации; живая публикация требует ключей вашего приложения.
- Оценка оставшегося времени загрузки — по текущей скорости и помечена как ориентировочная; для рендера показывается фактический прогресс FFmpeg без выдуманного ETA.
